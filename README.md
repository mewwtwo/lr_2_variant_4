# Лабораторна робота №2 - count_if

Компілятор: GCC, C++20. Потрібен TBB для політик виконання (`std::execution::par`).

## Чому GCC, а не Apple Clang

На macOS компілятор за замовчуванням - Apple Clang (`clang++`), і його стандартна
бібліотека `libc++` **не підтримує** політики виконання `std::execution::par`,
`seq`, `unseq`, `par_unseq` - код з ними просто не компілюється (`no member
named 'par' in namespace 'std::execution'`). Тому для цієї роботи потрібен
GCC - його `libstdc++` реалізує ці політики через бібліотеку Intel TBB.

## macOS

Встановити бібліотеки:

```bash
brew install gcc tbb
```

Зібрати і запустити:

```bash
make run
```

Це збере програму з `-O0` і `-O3` та запише вивід у
`results/output_O0.txt` і `results/output_O3.txt`.

## Windows (MSYS2)

Встановити бібліотеки (у терміналі **MSYS2 MinGW64**):

```bash
pacman -S mingw-w64-x86_64-gcc mingw-w64-x86_64-tbb
```

Зібрати і запустити:

```bash
mkdir -p results

g++ -std=c++20 -O0 -Iinclude src/*.cpp -o lab_O0.exe -ltbb -pthread
g++ -std=c++20 -O3 -Iinclude src/*.cpp -o lab_O3.exe -ltbb -pthread

./lab_O0.exe > results/output_O0.txt
./lab_O3.exe > results/output_O3.txt
```

## Дані

- якщо файли вже є - програма використає їх (однакові дані для `-O0` і `-O3`);
- якщо файлів немає - програма сама їх створить;
- щоб створити **нові** дані, запустити з параметром `--new`
  (новий випадковий seed, старі файли перезаписуються):

```bash
./lab_O3 --new
```

### Формат вхідних файлів

Файли `data/seq_N.txt` (N = 100000, 1000000, 10000000) - текстові:

- перший рядок - кількість чисел `N`;
- другий рядок - `N` цілих чисел з діапазону `[2, 100000]`, розділених пробілами.

```
5
17 4096 2 99991 50
```

Програма читає файл за ім'ям `data/seq_N.txt`, тому власні дані можна підставити,
зберігши цей формат і назву.

## Про -O0 / -O3

`-O0` вимикає оптимізацію компілятора: код перекладається майже дослівно,
без вбудовування функцій, розгортання циклів і векторизації - зате легко
дебажити. `-O3` - максимальна оптимізація: вбудовує функції, розгортає й
векторизує цикли, тримає змінні в регістрах - той самий результат, але
набагато швидше.
Це не про паралелізм (`par` проти `seq`), а про те, наскільки ефективний
машинний код взагалі згенерував компілятор.

- `-O0`: ~711 мс
- `-O3`: ~274 мс

Тобто сам рівень оптимізації дає ~2.6× прискорення без жодної зміни коду.

## Структура коду

Заголовки лежать в `include/`, реалізації - в `src/`.

`results/` - вивід програми, зібраної без оптимізації і з максимальною.
